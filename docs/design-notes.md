# 提出物④ ── 制作判断のメモ

## 何を記録するアプリか

「ヨルログ」は、寝る前5分で **3タップ＋ひとこと** だけ残す夜のジャーナリングアプリである。
記録するのは (1) からだ／こころの5段階、(2) 今日「効いた」「削られた」タグ、(3) 問いへの短い答え、の3つ。
自由記述に頼ると、疲れた夜には手が止まる。だから入力の主役をタップにし、
文章はあくまで補助にした。タップだけでも記録は成立し、まとめも生成される。

問いは白紙にしない。その日のコンディションから出し分け（こころが低い夜は出来事を外に置く問い、
調子が良い夜は良さの正体を言語化する問い）、さらに **前夜のAIが置いていった問いを翌晩の一番上に出す**。
「昨日は『思い出せない』と書いていました。今日は、覚えておきたい場面が1つありましたか」——
こう聞かれれば、白紙の前で止まらない。書けない夜のための「ことばが出ない夜」モードも用意し、
単語3つでも記録が閉じるようにした。入力の下限をほぼゼロまで下げることが、継続の設計だと考えた。

## まとめプロンプトの狙い

一般論に流れる経路を、プロンプトの側で塞ぐことに注力した。
SYSTEMで「本人が書いた語句を最低ひとつそのまま引用する」ことを毎回の制約にし、
「お疲れさま」「休息も大切です」のような誰にでも当てはまる文を名指しで禁止した。
各フィールドにはNG例とOK例を添えている（例文は審査サンプルと無関係な架空の記録を使い、
サンプルへの当て込みを避けた）。

複数日のふりかえりでは、生の日記だけを投げていない。
**「そのタグがついた日のこころ平均 − つかなかった日の平均」までアプリ側のJavaScriptで先に計算し、
数値の根拠として渡している。** そのうえで出力には〈数値〉と〈本人の言葉の直接引用〉の
両方を必ず入れるよう要求した。根拠を持たない断定が、そもそも書けない状態にしてからAIに渡している。
数値と本人の言葉が食い違ったときは本人の言葉を優先し、その食い違い自体を発見として書かせている。

## UXで意識した点

配色は夜間向けに、深い紺地へ暖色のアクセント。1画面に主要な操作をひとつだけ置き、
タップ領域は大きく、進捗は3本のバーで示した。
生成待ちは呼吸するような光ひとつに絞り、読み込み中の文字を減らした。
出力は「見出し → 引用 → 整理 → 気づき → 明日の問い」の順で、上から順に読むほど負荷が下がるよう並べている。
1項目は最大2文というプロンプト制約も、寝る前に読ませるための設計判断である。

## このアプリならではの工夫

**① 気づいていない回復スイッチ（blindspot）。** ふりかえりの筆頭に置いた出力。
「記録の上では効いているのに、本人が自分の成果として数えていないもの」を1つだけ返す。
本人が既に自覚しているものは除外させているため、要約では絶対に出てこない一文になる。

**② 回復スイッチのランキング。** 何が自分の調子を戻していたのかを、数値と自分の言葉の両方で示す。
筋トレのログを取るように、こころにも「効いた種目」があると見せる構造にした。

**③ まとめが次の問いを産む循環。** AIの出力に翌晩の問いを含め、それを翌日の入力ガイドに使う。
まとめが読み物で終わらず、次の記録の入り口になる。

**④ 見出しの背表紙。** その日に付いた見出しが日付とともに積み上がる。
7日分をスクロールすると、それだけで一週間が物語として読める。
「続けたのに変化が見えない」に対して、AIの生成を待たずに視覚で答える部分をつくった。

**⑤ 安全設計。** 深刻な語をローカルで検知して相談窓口を提示し、
プロンプト側でも診断・助言・決めつけを禁じている。判定はAIに委ねず、送信前にブラウザ内で行う。
